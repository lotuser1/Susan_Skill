# ma-deai · 去 AI 味

## 一句话定义

**先告诉你哪几句像 AI 写的，再把它改成人话，最后证明没改坏事实。**

三件事缺一不可。只打分不改，用户拿不到能发的东西；只改不核对，容易把「客户说没打过」改成「客户打过」，那是事故。

它**不做**的是：

- **不评价内容好坏**。AI 分低不等于写得好，只是不像模型写的
- **不代写新内容**。只改已有的稿子，观点和事实都是用户的
- **不查合规**。改完还得过一遍「合规文案审查」，两件事分开

---

## 使用前提

- Python 3（只用标准库）
- 不联网、不调 API、不上传内容
- 装了「面诊记录结构化」时，会自动比对该不该多出诊疗项目名

## 工作流（四步，第 3 步不许跳）

### 第 0 步：判断用户要什么

| 用户说的 | 怎么做 |
|---|---|
| 「这段像 AI 写的吗」 | 只跑第 1 步，给分数 + 具体哪几句 + 改法，不代改 |
| 「帮我去掉 AI 味」 | 走完四步 |
| 「这是数字人产出的口播稿」 | 走完四步，额外注意：口播稿要念得顺，句子要比书面更短 |
| 给的是整篇长文（>2000 字） | 先分段扫，挑出最重的 2–3 段改，别一次全改 |

### 第 1 步：扫描，把问题摆到桌面上

```bash
python3 "<本 Skill 目录>/scripts/scan_ai.py" 稿件.txt
```

输出三块：评分和等级、命中的特征（带原文证据）、按收益排序的改法。

**先把这份报告给用户看，再动手改。** 让他知道不是"我觉得像"，是有具体证据的——这一条决定他信不信后面改的东西。

分数参考：

| 分数 | 判断 | 怎么处理 |
|---|---|---|
| 0–20 | 人味足 | 不用改，直接说「这段没问题」 |
| 21–45 | 轻微 | 改掉列出的 2–3 处就行 |
| 46–70 | 明显 | 结构要动，逐条改 |
| 71–100 | 重度 | 建议按意思重写，微调没用 |

### 第 2 步：按三个动作改（顺序不能颠倒）

按 `references/改写规则.md` 执行：

1. **删** —— 整句删掉背景句、总结句、提示语（「值得注意的是」）、空号召。这是零风险的收益
2. **拆** —— 长句拆短，删「不仅…而且」这类关联词，去掉「首先其次最后」
3. **补** —— 补具体细节：数字、时间、地点、对话

**第 3 条有硬约束：补的细节只能来自原文或用户口述。**

原文没有、用户没说，就**不要编**。碰到这种情况只有两个合法做法：

- 问用户：「那天大概是几个人？有没有哪句客户原话你记得？」
- 不用细节，改成讲判断：「我一般先看她的下颌缘，再决定说不说这个方案」

编出来的细节看着最像人话，但客户一追问就穿帮，还可能变成虚假宣传。

### 第 3 步：校验事实（强制）

```bash
python3 "<本 Skill 目录>/scripts/check_rewrite.py" 改后.txt --source 原文.txt
```

它查五件事：新增数字、编造客户原话、长度失控（60%–130%）、AI 分是否真降下来、有没有多出原文没有的诊疗项目名。

- 有 `[失败]` → 重改，**不许交付**
- 最多 3 轮。3 轮还过不了，如实告诉用户哪一条改不干净、为什么

### 第 4 步：交付

三样，缺一不可：

1. **改后全文**（直接能复制的版本，不要只给片段）
2. **前后对比**：几分 → 几分，主要改了什么（列 3–5 条，不要列全部）
3. **一句实话**：这次改动的局限

## 六条硬规则

### 1. 不编事实

数字、时间、地点、客户原话、诊疗项目名，**原文没有就不能出现**。这是唯一一条不允许商量的规则。

### 2. 不把书面 AI 改成口语 AI

- ❌ 「姐妹们！这个项目真的绝了，冲」
- ✅ 「我做完第一周没啥感觉，第三周才开始有变化」

前者只是把 AI 腔换成了营销腔，AI 分可能降了，但仍然是套话。**AI 分的下降必须来自"更具体"，不是"更热闹"。**

### 3. 术语保留，黑话去掉

「三庭五眼」「下颌缘」「苹果肌」是行业共同语，删了反而不专业。
该删的是「赋能」「闭环」「底层逻辑」「颗粒度」这类换个行业也成立的词。

### 4. 不改用户的观点

可以改说法，不能改立场。用户说「我不建议年轻人做」，不能改成「年轻人也可以考虑」。

### 5. 字数不能砍半

删框架句是对的，但把一篇 800 字砍成 300 字就是另一件事了。校验脚本会拦在 60%。

### 6. 分数降不下来就说实话

有些文本天生 AI 分降不下去（比如通篇是定义和概念，没有具体事实可讲）。这时候正确做法是告诉用户：「这段要真正像人话，得补一个你自己的案例，我需要你提供。」

---

## 针对数字人口播稿的额外处理

数字人产出的是**念出来的稿子**，比书面稿多两个要求：

1. **句子更短**：一句超过 25 字，口播会喘不上气。目标 15–20 字
2. **去掉所有视觉标点依赖**：破折号、括号注释、分号，念出来是断的，改成句号

另外提醒用户：AI 数字人产出的内容发布时**必须带 AI 标识**（《人工智能生成合成内容标识办法》2025-09-01 施行），这个能力不负责加标识，但交付时要点一句。

## 输出格式

```markdown
## 去 AI 味 · 小红书口播稿

**扫描结果**：72 分（明显 AI 味）
- 时代背景式开头、总结式结尾、不是…而是 ×2、段落等长

**改后**（142 字，原 168 字）：
> 上周有个客人坐下就说，她这个脸是不是没救了。我先让她咬了下牙……

**改动清单**
1. 删掉开头「在当今…时代」整句，直接从客户那句话开始
2. 「不是…而是」拆成两句
3. 结尾「综上所述」整段删除

**校验**：AI 分 72 → 12，数字与项目名未变动，长度 85%
**一句实话**：这段没有新增细节，只是删掉了框架。要更有人味，得补一个你自己的面诊片段。
```

## 完成条件

- 跑过 `scan_ai.py`，并把命中证据给用户看了
- 跑过 `check_rewrite.py`，没有 `[失败]` 项
- 改后的 AI 分 ≤ 45（降不到要说明原因）
- 没有新增数字、原话、诊疗项目名
- 明确说了改了什么、以及这次的局限

---

## 边界与安全

- 全本地运行，不上传内容
- 稿件里的客户信息（姓名、单位、住址）改写时**不要补全、不要猜**
- 改写是草稿，发布前建议再用「合规文案审查」过全文
