# auto_transcribe

把本地成批的录音文件，通过**浏览器自动化**批量上传到「通义听悟」网页版做语音转写，并**开启多人讨论（说话人分离）**，自动区分不同发言人。

## 一句话定义

**把「一个目录里成百上千个录音」，批量上传到通义听悟转写、自动区分发言人；且每次运行都先比对听悟已有记录，绝不重复上传已经转写成功的文件。**

它解决的是：

- 本地录音很多，通义听悟网页一次只能手动传几十个，没法批量
- 要**区分发言人**（多人讨论）——这是通义听悟网页功能，百炼 API 不直接提供
- 重复运行、断点续跑时，**不能把同一个文件传两遍**造成重复文稿、重复扣额度

它不处理的是：

- 翻译、总结、润色文字稿——本 Skill 只负责把音频传到听悟并触发转写
- 视频转写（如需要，请先单独提取音轨）
- 实时语音识别（会议直播等）——只做已存音频的离线转写

> 与 `audio-to-text` 的区别：`audio-to-text` 走**阿里云百炼 API** 直接调 ASR（无需浏览器）；`auto_transcribe` 走**通义听悟网页版**（浏览器自动化），核心区别是「通义听悟高校师生账号有免费500小时转写时长」和「网页批量上传」。

## 技术原理

```
本地录音文件
   ↓ 启动带调试端口的 Chrome，手动扫码登录通义听悟（一次性）
本 Skill 通过 CDP 直连该 Chrome，操作网页：
   ↓ 打开「上传音视频」面板
   ↓ 每批投递 N 个文件（默认 20，避免面板拒收）
   ↓ 勾选「多人讨论」→ 开始转写
   ↓ 下一批……
幂等核心：上传前先调用听悟 getTransList 接口，
   对每个源文件判断其听悟状态：
     · 已成功(0) / 转写中(4) / 排队中(2) → 跳过
     · 仅失败(1) / 不在列表           → 才上传
   因此重复运行绝不会造出多余的「成功文稿」。
```

核心脚本：`scripts/auto_transcribe.py`，浏览器操作封装在 `scripts/tw_helpers.js`，CDP 驱动在 `scripts/cdp_helper.py`，听悟接口封装在 `scripts/tingwu_api.py`。

## 使用前提（必须满足）

1. 本机安装了 **Chrome**（普通 Chrome 或 Chrome for Testing 均可）。
2. 你已有**通义听悟**账号并登录（网页版 `https://tingwu.aliyun.com`）。
3. 录音文件**已在本地**（网盘文件需先下载到本地）。

> 为什么需要浏览器：通义听悟没有公开的「批量上传 + 多人讨论」开放 API，本 Skill 通过驱动你本机已登录的 Chrome 来完成网页操作。因此**必须先用本 Skill 提供的 `start_chrome.sh` 启动一个带远程调试端口的 Chrome 并扫码登录**，之后 Skill 才能通过 CDP 接管这个窗口。

## 环境变量配置（config.env）

复制 `config.env.example` 为 `config.env` 并填写：

```bash
# 【必填】要处理的录音文件夹，多个用逗号分隔
TINGWU_SOURCE_DIRS="/Users/你/录音文件夹A,/Users/你/录音文件夹B"

# 【必填】Chrome 远程调试端口；需先运行 start_chrome.sh 启动并登录
TINGWU_CHROME_PORT=9222

# 【可选】每批上传数量（默认 20；听悟面板对大批量会异步拒收，20 最稳）
TINGWU_BATCH_SIZE=20

# 【可选】单文件最多尝试次数，超过则判定顽固失败并跳过（默认 3）
TINGWU_MAX_ATTEMPTS=3

# 【可选】目标文件夹 URL（上传入口固定在通义听悟首页，此变量目前仅作记录，不影响上传）
TINGWU_FOLDER_URL="https://tingwu.aliyun.com/"

# 【可选】显式指定 Chrome 可执行文件路径（自动探测失败时填这里）
# CHROME_BIN="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
```

依赖安装（本机只需一次，仅需 websocket-client）：

```bash
python3 -m pip install websocket-client
```

## 用法

### 第 0 步：启动并登录 Chrome（只需一次）

```bash
bash start_chrome.sh
```

脚本会启动一个带调试端口的 Chrome 并打开通义听悟页面。**请在该 Chrome 窗口里用阿里云 APP / 支付宝 / 钉钉扫码登录**。登录完成后保持窗口打开，不要关。

### 第 1 步：先预览（dry-run，不真正上传）

```bash
bash run.sh --dry-run
```

会打印：源文件总数、已在听悟转写成功的、正在处理中的、需要新上传的、0 字节无法上传的。确认数字合理再继续。

### 第 2 步：正式上传

```bash
bash run.sh --apply
```

- 自动跳过已成功 / 正在处理的文件（幂等）
- 每批 20 个，校验面板实际接收数，未接收的单独补投
- 每批勾选「多人讨论」后开始转写
- **每批提交后都会去听悟核对这批文件的真实状态**：文件是否真的进入了「成功/排队/转写中」
- **额度不足自动停止**：若连续整批提交后都查不到成功记录（通义听悟免费额度耗尽时通常不直接弹窗，而是文件进列表后转写失败），会自动停止，绝不空转浪费时间
- 停止或跑完后，会把**仍未转写的文件清单写入 `pending_not_transcribed.txt`**（含完整本地路径），方便你充值后续传：`bash run.sh --apply` 会自动跳过已成功的、只补传剩余的
- **上传结束自动关闭调试 Chrome**：`--apply` 全部处理完（包括额度不足提前停止）后，会自动关闭那个带调试端口的 Chrome，**不会在界面留下"1 个后台任务运行中"**。下次上传请重新运行 `bash start_chrome.sh` 启动并登录。

### 只看当前状态

```bash
bash run.sh --status
```

只拉取听悟现有记录，告诉你每个源文件当前状态，不改动任何东西。

### 常用参数（直接传给 auto_transcribe.py 也行）

| 参数             | 作用                      | 默认           |
| -------------- | ----------------------- | ------------ |
| `--dry-run`    | 只计算并预览计划，不上传            | 开            |
| `--apply`      | 真正上传需要转写的文件             | 关            |
| `--status`     | 只报告当前听悟状态               | -            |
| `--dir`        | 临时指定单个目录（不改 config.env） | 读 config.env |
| `--batch-size` | 每批上传数量                  | 20           |
| `TINGWU_MAX_ATTEMPTS` | 单文件最多尝试次数（超限跳过并报告） | 3            |

## 批量配置（推荐给非技术用户）

把要处理的文件夹写进 `config.env` 的 `TINGWU_SOURCE_DIRS`，之后只运行一行：

```bash
bash run.sh --apply
```

想临时只处理某个目录：

```bash
bash run.sh --apply --dir /某个/具体/目录
```

## 关键行为与边界

- **幂等去重（最重要）**：上传前逐文件核对听悟状态，**已有成功文稿或正在处理的文件直接跳过**，绝不为同一个录音创建第二条成功任务。可以放心反复运行、断点续跑。
- **只读不删**：不改动、不删除你的原始录音，只在听悟网页端创建转写任务。
- **凭证不硬编码**：本 Skill 不需要任何 API Key（直接用你已经登录的 Chrome 会话），所有路径走环境变量。
- **0 字节文件跳过**：源目录里 0 字节的损坏录音会被单独列出并跳过（听悟收不了），需你回源头重新导出。
- **"离开此页面"弹窗自动处理**：通义听悟在切换页面时会弹出"是否离开此页面"确认框。本 Skill 已从源头抑制该弹窗，并在极少数仍弹出时自动放行导航（而非取消——取消会中止导航、导致上传面板打不开而卡死）。**你不需要在弹窗里手动点"取消"**，保持 Chrome 窗口打开即可，脚本会自动继续。
- **时长/额度不足自动停止**：通义听悟耗尽免费额度时往往不弹阻断弹窗，而是文件能进列表、但转写失败。本 Skill 每批提交后核对真实状态，一旦「连续整批都未能成功入列」即判定额度不可用并停止，同时把未转写清单写入 `pending_not_transcribed.txt`，绝不盲目续传计费。
- **顽固文件三次失败后跳过**：个别文件可能因格式/时长超限或听悟偶发拒收而反复传不上去。本 Skill 会**持久记录每个文件的尝试次数**（存于 `state.json` 的 `attempts` 字段），当某文件累计尝试达到 `TINGWU_MAX_ATTEMPTS`（默认 3）次仍无成功/处理中记录时，**自动跳过不再重试**，并在任务结束时把这批顽固文件的文件名输出到屏幕、同时写入 `skipped_stubborn.txt`（含完整本地路径），方便你单独排查，而不是无限重试卡住整个流程。后续若想强制再试，删除该文件在 `state.json` 的计数即可。
- **上传结束自动关闭调试 Chrome**：`--apply` 走完（正常完成或额度不足提前停止）后会自动发 CDP 命令关闭带调试端口的 Chrome，释放常驻进程，界面不再显示"1 个后台任务运行中"。关闭是优雅关闭（browser 级 `Browser.close`），不影响任何已上传数据。下次上传前请重新运行 `bash start_chrome.sh` 启动并登录。`--dry-run` 与 `--status` 不会关闭 Chrome（它们是诊断命令，需保留会话）。
- **安全边界**：只在你本机已登录的 Chrome 上操作通悟；不会把音频外发到除阿里云（通义听悟）以外的第三方。

## 为什么之前会"转写文档数超过录音数"（已修复）

早期版本是「盲传」：22 批全部上传，从不去查文件是否已在听悟成功；重传时又重复提交，导致同一录音产生多条成功任务。本版本在上传前强制做一次**全量状态核对**，只上传"尚无成功记录"的文件，从根本上杜绝重复成功文稿。

## 找回文稿 / 导出

转写完成后，在通义听悟网页端「默认文件夹」里可以批量勾选、导出 Word / 字幕。本 Skill 只负责"上传 + 触发转写"，不负责导出（导出请在网页端操作，或后续接别的 Skill）。

## 与 dbs-knowledge 衔接

转写完成并从听悟导出文字稿后，把文稿目录交给 `/dbs-knowledge` 搭建知识库：

> 把我这个录音文字稿目录建成知识库，按课程板块归档，支持按板块查找。

这样「录音 → 听悟转写(区分发言人) → 文字稿 → 知识库」链路就闭环了。
