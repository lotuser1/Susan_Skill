# ma-consult-note · 面诊记录结构化

## 一句话定义

**把一段乱糟糟的口语对话，整理成一份能直接归档、能拿来做复盘的客户档案。**

它解决的是：

- 面诊聊完就忘，客户第二次来要重新问一遍（客户会觉得你不专业）
- 手写记录只有几个关键词，过一个月自己都看不懂
- 客户说过"我上次在别家打过某某"，但没人记下来，方案做重了
- 团队交接时，客户信息全靠口头传，传两遍就变形

它**不做**的是：

- **不评价聊得好不好**。只记录发生了什么，判断好坏是「聊客复盘诊断」的事
- **不给医学诊断**。客户脸上的问题只记"谁说了什么"，不做病理判断
- **不编造任何信息**。原文没有的一律写「未提及」，这是硬规则

---

## 使用前提

- Python 3（脚本只用标准库）
- 有转写稿最好。**没有原稿也能整理，但无法校验，容易掺入推测** —— 这种情况下必须在交付时明确说明
- 全程本地运行，录音和档案不上传任何地方

## 工作流（按顺序走，第 4 步不许跳）

### 第 0 步：判断输入形态

| 用户给的是什么 | 怎么做 |
|---|---|
| 带 `【说话人N】[时间]` 的转写稿 | 走完整流程 |
| 纯文字聊天记录（微信导出） | 走完整流程，脚本会自动降级处理 |
| 一段口述、没有原稿 | 跳过第 1 步，直接按字段整理，**交付时说明"无原稿，未经校验"** |
| 图片/截图 | 先转成文字再开始，不要凭图片描述编内容 |
| 只有零散几句话 | 能做，但档案大部分会是「未提及」。如实呈现，别硬填 |

### 第 1 步：预处理

```bash
python3 "<本 Skill 目录>/scripts/prepare.py" "<转写稿路径>" --out /tmp/consult-note
```

读它输出的三样东西：

1. **日期** —— 档案的会话日期
2. **说话人推断** —— 谁可能是咨询师、谁是客户、谁是陪同。**这只是参考，最终要你按内容确认**
3. **数字锚点** —— 原文里出现过的所有金额、剂量、年龄。后面档案里出现的数字必须来自这里

长稿会切成多块写进 `chunks.md`。

### 第 2 步：逐块提取（长稿必须分块，不许跳读）

对每一块单独提取，产出**局部笔记**：这一块里出现了哪些字段的信息、原话是什么、数字是什么。

**为什么不一次读完**：5000 字以上的稿子，一口气读完必然漏掉中段。真实面诊的信息是散落的 —— 客户可能在第 3 分钟提一句"我以前打过"，在 20 分钟又补一句"就是那个针，打完脸变宽了"，这两句必须合并到一起。

### 第 3 步：合并成档案

按 `references/档案字段表.md` 的字段定义，套 `references/输出模板.md` 的格式。

合并规则：

- 同一字段多次提及 → 合并，时间靠后的为准
- 前后说法矛盾 → 两条都留，标 `（前后说法不一致）`
- 后段补充的信息 → 补进已有字段，不要新开字段

### 第 4 步：校验（强制，不许省略）

```bash
python3 "<本 Skill 目录>/scripts/verify.py" "<档案路径>" --source "<原稿路径>"
```

它会逐条核对：

| 检查什么 | 抓什么问题 |
|---|---|
| 必备字段 | 漏了主诉、既往史、异议这类关键部分 |
| 原话可追溯 | `【原话】` 引的内容在原文里找不到 |
| 数字有依据 | 金额、剂量、年龄编造或记错 |
| 项目名有依据 | 档案提到某个项目，原文没出现过 |
| 易混项目 | 原文说超声刀，档案写成超声炮 |
| 越界表述 | 出现了诊断结论或"聊得不好"这类评价 |

**有「必须修」就改，改完重跑。最多 3 轮**，还不通过就把无法确认的项如实列进缺口清单，不要蒙。

### 第 5 步：交付

交付物是三样，缺一不可：

1. **档案正文**（按模板）
2. **本次档案缺口** —— 未询问 / 未提及 / 待确认，这一段比档案本身更有用
3. **一句实话** —— 如果有无原稿、有 `[?]` 待确认、有前后矛盾，明确说出来

## 六条硬规则（违反了档案就是废的）

### 1. 每个字段必须带来源标注

`【原话】` / `【转述】` / `未提及` / `未询问`，四选一。

### 2. `未提及` 和 `未询问` 不能混

- `未提及`：聊到了这个话题，客户没说自己的情况
- `未询问`：整个对话**根本没人问过**

这个区别决定下一步补什么：前者补追问，后者补流程。

### 3. 否定、假设、他人转述，三种句型最容易记错

| 原话 | ✅ 正确 | ❌ 错误 |
|---|---|---|
| "我没打过水光" | 明确否认注射类 | 打过水光 |
| "要是便宜点我就做" | 条件性意向，价格敏感 | 已确认要做 |
| "我朋友在你们这做的" | 来源：老客转介绍 | 客户做过项目 |
| "我妹打了瘦脸针脸垮了" | 顾虑来源：见过负面案例 | 客户打过瘦脸针 |

### 4. 数字必须有原文依据，没有就写「未提及」

金额、剂量、年龄、次数 —— 一个都不许估。

**金额尤其要分清"报价"和"成交价"**：咨询师说"这个 6800"是报价，客户没掏钱就不是成交价。这是最常见的失真。

### 5. 项目名听不清就标 `[?]`，不许猜

ASR 会把"超声炮"转成"超生炮"，把品牌名转成一堆同音字。

- ✅ `2024 年打过奥斯尼[?]（需客户确认具体材料）`
- ❌ `2024 年打过超声炮`

猜错的后果不是档案难看，是方案做重、剂量算错。

### 6. 只记录，不评价，不诊断

- ✅ `【转述】医生提到"面中部有点空，下颌缘有点松"`
- ❌ `客户属于典型的面中部容量缺失伴下颌缘松弛`

- ✅ `客户问了 3 次价格，咨询师回答了 2 次`
- ❌ `价格异议处理不到位，应该先塑造价值`

如果用户主动问"我聊得怎么样"，如实告诉他：这个能力只做整理，判断需要复盘诊断。

## 输出格式

默认完整档案。用户说"简单点""我要贴系统"用一页纸，说"导进系统"用 JSON。三种模板都在 `references/输出模板.md`。

---

## 完成条件

- `verify.py` 没有「必须修」项
- 缺口清单写了（哪怕全是「未提及」）
- 明确告诉用户：档案里哪些是待确认的、哪些没问过
- 全程没有出现诊断结论或好坏评价

---

## 边界与安全

- **只读原稿**：不修改用户的录音和转写文件
- **全本地**：不联网、不调 API
- **脱敏**：姓名写成 `【客户】`，手机号微信号标 `[已脱敏]`
- **提醒一次**：档案含客户隐私，对外分享前请自行再脱敏

## 文件说明

| 文件 | 作用 |
|---|---|
| `references/档案字段表.md` | 字段定义、三级标注规则、缺口处理 |
| `references/提取规则.md` | 22 条口语转结构化的防错规则 |
| `references/输出模板.md` | 完整档案 / 一页纸 / JSON 三种格式 |
| `references/项目词表.json` | 项目、品牌、部位、易混项目对照 |
| `scripts/prepare.py` | 预处理：角色推断、长稿切块、数字锚点 |
| `scripts/verify.py` | 反幻觉校验 |
| `scripts/selftest.py` | 回归自测（用虚构对话验证校验逻辑没坏） |
| `run.sh` | 自动找 Python 的入口，参数见文件开头 |

也可以用 `bash run.sh prepare 原稿.md` / `bash run.sh verify 档案.md --source 原稿.md`
代替 `python3 scripts/...`，Windows 上找不到 python3 命令时用这个。

改字段先改字段表，改词表直接往 JSON 里加。改完脚本必须跑一次：

```bash
python3 scripts/selftest.py
```

4 项全过才算没改坏。它会用一段虚构对话验证：正确档案能通过、金额编造能抓出、
既往史记反能抓出、项目写错能抓出。**只改了 `verify.py` 的逻辑却没跑过自测，不要发版。**
