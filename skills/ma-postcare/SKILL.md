# ma-postcare · 术后须知生成

## 一句话定义

**按项目查时间轴，出一份客户看得懂、合规又不会被投诉的术后交代。**

它不是让模型"写一段话"，而是**从固定时间轴库出稿**——因为这个场景错了不是文案问题，是医疗误导。

它**不做**的是：

- **不给诊断**。客户问"我这是不是感染了"，只能让他联系医生
- **不给用药建议**。药名剂量属于医嘱
- **不承诺恢复时间**。"三天就好"是违规话术
- **不替代医生**。每份输出都必须有"以主诊医生交代为准"

---

## 使用前提

- Python 3（只用标准库）
- 不联网、不调 API
- 时间轴库覆盖 13 个项目：注射类（水光/玻尿酸/肉毒素）、光电类（光子/皮秒/点阵/热玛吉/超声炮）、化学焕肤、手术类（双眼皮/隆鼻/吸脂/脂肪填充）

## 工作流（四步，第 3 步不许跳）

### 第 0 步：确认三件事

| 要确认的 | 为什么 | 不知道时怎么办 |
|---|---|---|
| **哪个项目** | 时间轴完全不同 | 问清楚。客户说"做了个光"要追问是光子还是皮秒 |
| **给谁看** | 私发客户 / 打印贴诊室 / 发朋友圈，三种写法 | 默认私发客户 |
| **主诊医生是谁** | 免责句要指名 | 不知道就写"主诊医生"，不要编名字 |

### 第 1 步：查库，别自己编

```bash
python3 "<本 Skill 目录>/scripts/build.py" --list
```

**没收录的项目，不许自己编时间轴。** 直说：

> 「精灵耳这个项目还没收录时间轴。我不能凭空写恢复期给你——写错了客户照着做会出事。要么你告诉我你们机构的实际交代，我按你说的整理；要么我先把通用框架给你，具体时间你们医生填。」

这条比什么都重要。宁可少做一个项目，不能编一个。

### 第 2 步：生成初稿

```bash
# 私发客户
python3 scripts/build.py --project 水光针 --format wechat --name 王女士 --doctor 李医生

# 打印版（带勾选框，可随病历）
python3 scripts/build.py --project 双眼皮 --format print --name 王女士

# 朋友圈 / 公众号（只讲共性，不留客户信息）
python3 scripts/build.py --project 热玛吉 --format moments
```

三种格式的差别不只是长度，是**能不能带客户信息**：朋友圈版一个字都不能带。

### 第 3 步：按客户情况微调（有边界）

**可以做的**：

- 加一句针对性的提醒（"你皮肤偏薄，防晒要比平时更严"）
- 删掉不适用于这个项目的内容（比如无创项目删掉"拆线"）
- 按机构习惯调整称呼和结尾

**不可以做的**：

- 改时间轴里的天数（要改就改库，不要在这里改一份）
- 加库以外的医学结论（"你这个体质恢复会慢"——这是诊断）
- 加药物、剂量、频次
- 删掉免责句

### 第 4 步：校验（强制）

```bash
python3 scripts/verify.py 须知.md --format wechat
```

查九项：免责句、就医出口、时间分段、时间承诺、绝对化、恐吓话术、诊断句、具体用药、术后对比。

- 有 `[失败]` → 改，改完重跑
- 连续两轮不过 → 说明改动偏离了库，回到第 2 步重新生成，不要在错稿上打补丁

## 七条硬规则（违反任何一条不能发）

### 1. 不承诺恢复时间

- ❌ 三天就好了
- ✅ 一般 1–3 天会逐渐消退，具体看个人恢复

### 2. 不吓人

- ❌ 出现红肿赶紧去医院，否则毁容
- ✅ 如果红肿持续加重，联系你的主诊医生看一下

**把"后果"换成"动作"**——不说你会怎样，说你该做什么。

### 3. 不下诊断

- ❌ 你这是感染了
- ✅ 有没有感染需要医生看，先拍张照片发给主诊医生

### 4. 不给具体用药

- ❌ 每天吃两次头孢
- ✅ 按医生开的药和剂量吃，不要自己加量

### 5. 必须有免责句

每份输出结尾都要有：**「以上是常见情况，具体以主诊医生的当面交代为准。」**
没有这句，整份文档就是在替医生下医嘱。

### 6. 不写"不用复诊"

- ❌ 恢复得好就不用来了
- ✅ 按约定时间复诊，医生看过后再决定下一步

### 7. 不发术前术后对比

术后须知里一张对比图都不要有，这是医疗广告高风险项。

## 交付时要说的三句话

每次给用户成品，主动带上这三条：

1. **时间轴要核对**：「时间范围是行业常见区间，你们机构的方案如果不一样，告诉我我改库」
2. **客户信息已脱敏**：私发版只带称呼，公开版一个信息都没有
3. **这是交代，不是医嘱**：客户有异常必须联系医生，不要让内容替代面诊

## 完成条件

- 项目在库里（不在库里要明确说"不能编"，并给替代方案）
- 跑过 `verify.py`，没有 `[失败]` 项
- 免责句在、就医信号在、时间分段 ≥3 处
- 朋友圈版没有客户信息
- 交付时说了"时间轴要按机构核对"

---

## 边界与安全

- 全本地运行，不上传内容
- 时间轴是**行业常见区间**，机构使用前必须按自己方案核对，这一点要写在交付里
- 本能力只做"交代"，不做诊断、不做用药建议；客户有异常一律指向线下医生

## 文件说明

| 文件 | 作用 |
|---|---|
| `references/术后时间轴.json` | 13 个项目的分阶段反应、护理、就医信号、复诊时间 |
| `references/合规红线.md` | 八条红线与替换写法，含三种场景的语气差别 |
| `scripts/build.py` | 按项目出三种格式（私发/打印/朋友圈） |
| `scripts/verify.py` | 九项合规与结构校验 |
| `scripts/selftest.py` | 回归测试，改库或改脚本后必须跑 |
| `run.sh` | 自动找 Python 的入口 |

**加新项目**：往 `术后时间轴.json` 的 `projects` 里加一条，字段照现有抄，然后跑：

```bash
python3 scripts/selftest.py
```

14 项全过才能发版——它会把每个项目都生成一遍并校验，写漏免责句或就医信号的项目会立刻暴露。
